# HIP Port of the CUDA Component — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the existing `cuda/src` component unchanged in structure for AMD GPUs through HIP, from one source tree, and pass the CUDA hardware parity suite on an RX 7600 XT (gfx1100).

**Architecture:** Futhark-style platform preludes. CUDA spelling stays the kernel and host dialect (as Futhark's HIP backend reuses `rts/cuda/prelude.cu`). Two headers absorb the platform: `gpu_runtime.h` (host API: on HIP, `cuda*` names alias `hip*`) and `gpu_device.h` (device built-ins without a 1:1 mapping get neutral `BEAMZ_*` macros). One CMake option selects the platform and the module name (`beamz._cuda` or `beamz._hip`); Python picks the module and the XLA platform from JAX's GPU client.

**Tech Stack:** CUDA 13 / nvcc, ROCm 7.2 / hip-clang, CMake ≥ 3.24 (`LANGUAGE HIP`), scikit-build-core, nanobind, XLA FFI, JAX 0.9.x (`.venv` CUDA, `.venv-rocm` ROCm).

**Spec:** this conversation's design (2026-11-06): "apply the Futhark platform-macro approach to the CUDA code so it runs on HIP". Phase 1 = correct and bit-identical-to-JAX-tolerance on RDNA3 with the untuned (conservative) schedule. Per-architecture tuning is a separate, later plan.

## Global Constraints

- CUDA builds must stay semantically identical: on CUDA every new macro expands to exactly the previous token sequence.
- One source tree; no hipified copies, no generated `.hip` files checked in.
- HIP device code compiles with `-ffp-contract=off` and without `-ffast-math` (hipcc contracts by default; the kernels pin rounding with `__fmaf_rn`/`__fmul_rn`).
- Phase 1 HIP architectures: RDNA only (wave32). Default `BEAMZ_HIP_ARCHITECTURES=gfx1100`; CMake rejects `gfx9*` (wave64) until the warp code is width-generic.
- `backend="auto"` never selects the HIP build in phase 1; it is explicit opt-in (`backend="cuda_streamed"` / `"cuda"`), like the Futhark backend.
- AMD runs: the RX 7600 XT drives the desktop. Env `HSA_OVERRIDE_GFX_VERSION=11.0.0 ROCR_VISIBLE_DEVICES=0`, `XLA_PYTHON_CLIENT_PREALLOCATE=false`; only shapes ≤ ~1 M cells without asking.
- Verified 2026-11-06: by-value kernel arguments of 8 KB launch correctly on ROCm 7.2 (BeamzLaunch ≈ 4.1 KB, BeamzAdjointLaunch ≈ 7.5 KB), so launch structs stay by value.

## Review Focus

1. ROCm JAX reports `compute_capability == "gfx1100"`; `_compute_capability` must not raise (today `int("gfx1100")` would). → Task 4 test.
2. Both `_cuda` and `_hip` `.so` may sit in the same editable tree (both venvs are cp311): the CUDA venv must never load `_hip`, nor ROCm load `_cuda`. → Task 4 test.
3. `#ifdef __CUDA_ARCH__` / `__CUDACC__` are undefined under hip-clang, so device code silently takes host branches (e.g. `sharded_numeric.h` would use contractible `a*b+c`). → Task 1 source-scan test.
4. Forced overrides (`BEAMZ_CUDA_TEMPORAL_STEPS=2`, `BEAMZ_CUDA_CPML_CORE_FUSION=1`, mstep) request shared memory sizes tuned for SM86; on AMD a too-large request must surface as an error, not wrong fields. → Task 5 runs the override parity tests.
5. The SM86 gate (`program.cu:505`) must evaluate false on AMD (HIP reports gfx major 11) so the default schedule is the conservative one. → Task 5 asserts `native_plans` in one run.

## Findings during execution (2026-11-06)

- `platform_version` on ROCm PJRT is `"PJRT C API\nrocm 70200"` (two lines); detection checks every line.
- HIP needs: `hipGraphInstantiateWithFlags` for CUDA 12's 3-argument `cudaGraphInstantiate`; a template wrapper for `hipFuncSetAttribute` (takes `const void*`); 64-bit lane masks; `__float2bfloat16` (already round-to-nearest-even) for `__float2bfloat16_rn`; parentheses around template-comma arguments of `__launch_bounds__`, which is a macro on HIP. By-value kernel arguments up to 8 KB work on ROCm 7.2.
- Pre-existing bug, not HIP-specific: `EnqueueMstepTile` sent constant-block (rank-2) E materials to the lean `MstepPackedColumnCore`, which decodes only 8-bit codes and reads ~8x past the header array. CUDA (sm_75, `main`) produced garbage silently (36 mstep failures); AMD page-faulted. Fixed by routing block-format materials to `MstepColumnCore<Packed=true>`.
- The AMD card must not drive the display during suites (GPU reset/desktop freeze on 2026-11-06); the display is on the iGPU now.
- Pre-existing failures on `main` independent of platform: 4 non-uniform-grid tests (raster `TypeError`), `extended_feature_envelope[conductive]` (NaN location mismatch). Turing-only CUDA failures: 12 `temporal_pair`, 2 autodiff VJP cases (pass on AMD).
