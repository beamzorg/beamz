The changes address ownership and preparation rather than changing the CUDA numerical kernels:

- Place native preparation on CPU. This removes roughly 4.3 GB of retained accelerator-side preparation storage from the earlier bridge. CPU preparation is still included in complete-notebook timing.
- Reuse the already-owned host initial state for fresh-run resets instead of keeping another 646.1 MB GPU snapshot. Host reset takes approximately 35 ms and is included in public/end-to-end timing.
- Replace the bridge's duplicate JAX initial state with mapped captured initial values, then release trace arguments and unused workspaces before upload.
- Defer 73.7 MB of plan inputs used by ordinary Mstep, since moving CUDA constructs its own scheduling plan. The ordinary method materializes those inputs when called. Existing 281 MB lazy scratch remains deferred during moving execution.
- Upload mapped inputs one at a time, synchronizing each copy before releasing its read-only staging pages. Copy-on-write caller mappings retain their private modifications; a regression check and a failing negative control verify that distinction.
